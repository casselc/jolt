## Integration method

The live release lineage is joined to the canonical aspect branch with a
history-only merge. Its second parent is the live release commit, while its
tree is exactly the canonical first parent's tree. This is intentional: a
content merge would replay a tree already present through the original release
lineage and conflict with subsequent upstream and aspect work. Identical
release trees prove that the history-only merge discards no v0.8.6 content.

After that merge, the schema 3 lock records the live release commit and the
tree-equivalent v0.8.3 commit in its lineage. The verifier still requires the
historical v0.8.3 base as the aspect root's parent, proves that both v0.8.3
commits have the same tree, proves live-lineage ancestry from that base to the
release, and requires the current revision to contain both histories. Online
verification also checks the live tag identity and release tree. No aspect
commit is rebased or rewritten.
