## Q1 — Judgment honesty and the A3 promotion gate
- **[major] The gate has no forcing artifact.** `DECISION-MEMO-2026-08-01.md:150-151` ("promotion to A3 requires a named consumer and a fresh review") names no mechanism that fires when someone adds an A3 field. Nothing in C1 or C5 makes the CSIR v1 schema *closed*; an open schema lets expansion-chain or anchor fields accrete without any review trigger. The concrete artifact that would make the gate real: declare the v1 schema closed (unknown fields = validation failure) in the C1 field list, so any A3 feature necessarily forces a schema remint, which C5 routes to the core lane and C1's own text subjects to fresh review. Observation: the validator is assigned an owner (`MEMO:156`) but no strictness rule.
- **[major] The gate already leaks in D1's accepted text.** `MEMO:26-28` commits declared anchors ("Declared anchors may preserve identity…") as part of the stage-independent identity rule, and P6:30 identifies declared anchors + expansion-parent chain as precisely A3's extra feature over A2 (P2:48 confirms anchors appear only under A3). So the "A2-minimal is the only committed build" claim (`MEMO:150`) is contradicted by D1 itself: the A3-distinguishing mechanism is committed at all stages with no consumer. Honesty about the *judgment* (C1 does record it plainly, `MEMO:148-149` — verified, matching P6:29-31's demand) does not extend to the *rule text*.
- **[minor] Ossification direction is asymmetric and benign-but-unstated.** A2-minimal silently becoming permanent is the *cheap* failure (you keep the smaller artifact); the memo treats it as a risk without noting that the dangerous drift direction is A3-creep, which is the direction the leak above enables. One sentence fixes this.
- Strongest counterargument to my own finding: single-step `expansion parent` in C1's v1 field set (`MEMO:153-154`) is arguably within A2's "macro stack" (P2:37), so C1's field list itself is not a leak — only the anchor clause in D1 is. I accept that; the finding stands on anchors alone.

## Q2 — Site-ID stability under the macro-digest chain
- **[blocker] Definition-digest chain causes spurious global ID churn.** (a) Editing a library macro without changing its expansion at a given site (new arity, a branch never taken there, a docstring-adjacent body tweak) changes the definition digest → chain → every downstream site-ID at every call site, violating the rule's own promise that structure-preserving change retains the ID (P2:55). (b) A dependency version bump with any transitive macro edit breaks IDs across every consumer namespace at once, dangling all D3 evidence records keyed to them; the only remedy in the design is declared anchors, which require *reviewer approval per anchor* (`MEMO:26-28`) — routine dep bumps would industrialize anchor approval into rubber-stamping, destroying the Q3 control. Live grounding: nested expansion is re-expanded level-by-level (`host-contract.ss:240-241`, `analyzer.clj:1012-1024`), so the chain is real and its length varies with macro nesting depth — churn multiplies through macro-heavy code. Fix: derive the ID from the digest of the **normalized expanded form at the site** (which changes iff the expansion actually changes there) and demote the macro-definition digest chain to CSIR provenance *metadata outside the ID*.
- **[major] The definition digest may not be computable at all for prebuilt libraries.** `host-contract.ss:285-295`: the expander is `(var-cell-root (hc-resolve-cell ctx head))` — an opaque compiled closure; no source form exists at expansion time. Recording a digest requires new definition-time capture in the `:defmacro` path, and for direct-linked/prebuilt artifacts (P1:96) the defmacro *source* may not ship at all. Inference from verified mechanism; the memo nowhere stages this dependency.
- **[major] "Normalized expanded semantic-role path" is not implementable deterministically by two engineers as written.** No document in scope defines the normalization. At minimum unstated: gensym canonicalization (expansions embed gensym'd locals whose names differ across compiles of identical source — inference from standard gensym behavior, not verified in jolt source), sibling indexing for `:do`/`:let` positions (ir.clj:120-124), chain ordering for the re-expansion recursion, and treatment of `hc-propagate-pos`-merged metadata. Fix: v1 exit test (C1, `MEMO:157-158`) must include cross-implementation ID test vectors, and the normalization algorithm must be a normative charter appendix.
- **[minor] Schema-inside-ID is correct, with one missing declaration.** Under P2:57's remint policy (no compatibility reader for prerelease schemas), IDs *should* die with the schema — but the memo must say explicitly that a remint orphans all prior evidence records; post-v1, a remint must emit an old-ID→new-ID migration record for surviving sites. IDs surviving remints silently would be worse (unversioned identity); the current design errs the right way but silently.

## Q3 — Declared anchors: strongest abuse case
- **[major] The digest pair documents; nothing prevents evidence carry-over.** Abuse construction: refactor a public operation with a real behavioral change (e.g., reordering effects that D6's fragment doesn't formalize), declare an anchor "intentional refactor", get approval, and downstream evidence aggregation now treats pre-change `monitored`/`sampled` records as continuous history for the "same" operation — the disclaimer "an anchor never asserts behavioral equivalence" (`MEMO:28`) constrains what the anchor *asserts*, not what consumers *infer* from ID continuity. D3's claim-relative order (`MEMO:43-45`) could block this — evidence relates only for same proposition/scope — but nothing states that an anchor crossing is a scope change. Fix: rule that evidence levels never transfer across an anchor; post-anchor claims restart at `assumed` until re-evidenced against the new digest. The anchor grants attribution/history continuity only.
- **[major] No machine-checkable semantic-preservation rule exists, and the memo should say so.** General behavioral equivalence is undecidable; the honest design is: (i) admit reviewer judgment is the control; (ii) mandate a partial mechanical check — the anchored operation's conformance/differential corpus (the C1 exit-test machinery) must pass identically on old and new digests, with the run's evidence ID recorded in the anchor; (iii) mandatory anchor record contents: old/new CSIR digests, normalized-expansion diff, differential-run evidence ID, reviewer identity, and a stated equivalence argument. Currently `MEMO:26-28`/P2:55 require only digests + approval — P7:85's "anchor-as-false-equivalence" worry is confirmed as unmitigated by the recorded pair alone.
- **[question]** Who may *consume* anchors in v1? If the A2-minimal milestone has no anchor consumer (per C1), are anchors even declarable before A3 promotion? If yes, the Q1 gate leak widens; cleanest answer: anchors are undeclarable in v1 (schema-closed), which resolves Q1 and Q3 together.

## Q4 — C4 one-ID-space consequences
- **[major] (a) Unification is unachievable for host-origin operations; "when one exists" is a dangling case.** All Jolt-compiled code passes the analyzer (`analyzer.clj:1012-1029`) and can get CSIR nodes, including FFI call sites (`:ffi-fn` ir.clj:138). But the host layer itself is handwritten Scheme (`host/chez/*.ss` — e.g. concurrency.ss futures, dyn-binding.ss) that never traverses the analyzer, and callbacks fired from native threads have a Jolt *registration* site but no Jolt *firing* site. C4's "carries the site-ID of the widening site… when one exists" (`MEMO:192-194`) gives no rule when none exists. Fix: descriptors must carry either a CSIR site-ID or a member of a reserved, enumerated `host-origin` ID class (e.g., the registration site's ID plus an entry-kind tag); a null/absent site-id is a validation failure.
- **[major] (b) Eval collapse degrades runtime attribution and must be declared.** Eval'd code is analyzed by the resident compiler (P1:91, `compile-eval.ss:304-311` — cited per P1, not independently re-read), so finer IDs are *technically producible*; C4 forbids them deliberately. Static-claim discipline is coherent (Dynamic-opaque admits no static claims anyway), but *monitored/sampled runtime* evidence for a plugin-style app collapses: every operation performed by eval'd code shares one site-ID, and discrimination falls entirely to descriptor `{family operation operation-id canonical-args}` (`MEMO:60-61`) — and whether `operation-id` is per-kind or per-instance is defined nowhere in scope **[question]**. Fix: state that attribution granularity inside Dynamic-opaque regions is descriptor-level, and define `operation-id` cardinality.
- **[minor] (c) Remint dangles production evidence; D3 detects but does not preserve.** One ID space means a CSIR schema remint (Q2) invalidates descriptor `site-id`s in *runtime* evidence records, not just proof artifacts. D3's mandatory schema/IR-version metadata (`MEMO:53-57`) makes stale records detectable — adequate for honesty — but there is no migration path, so incident-trace continuity dies at every prerelease remint. Acceptable if declared (ties to Q2's migration-record amendment); silent today.

## Proposed amendments (smallest set that resolves the findings)
- **F1 (Q1):** CSIR v1 schema is **closed** — unknown fields and anchor records are validation failures; any A3 field requires a schema remint, which requires a memo amendment naming the consumer. Move D1's declared-anchor sentence from the stage-independent rule into the A3-conditional text.
- **F2 (Q2, blocker):** Site-ID derives from the digest of the **normalized expanded form at the site**, not the macro-definition digest chain; the chain becomes CSIR provenance metadata outside the ID. Stage the definition-time source-capture dependency explicitly if the chain is kept even as metadata.
- **F3 (Q2):** Add a normative normalization algorithm (gensym canonicalization, child indexing, chain order) as a charter appendix; C1's exit test gains cross-run/cross-implementation ID determinism vectors.
- **F4 (Q2/Q4c):** Declare: prerelease remint orphans all evidence records (detectable via D3 metadata, never silently reinterpreted); post-v1 remints must emit an old-ID→new-ID migration record.
- **F5 (Q3):** Evidence never transfers across an anchor — post-anchor claims restart at `assumed`. Anchor record must carry: old/new digests, normalized-expansion diff, differential-corpus run evidence ID, reviewer identity, equivalence argument. Anchors undeclarable in v1 (subsumed by F1).
- **F6 (Q4a):** Every descriptor carries a CSIR site-ID or a reserved enumerated host-origin ID (registration site + entry-kind); absent site-id is a validation failure. Delete "when one exists".
- **F7 (Q4b):** Declare Dynamic-opaque attribution granularity as descriptor-level; define `operation-id` cardinality (per-kind vs per-instance) in D4.
